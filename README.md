# Личный трекер задач

Однопользовательский таск-трекер: дашборд, таблица, канбан-доска, календарь
и карточка задачи. Без бэкенда — данные лежат в браузере, копия выгружается в файл.

## Запуск

```bash
npm install
npm run dev
```

Откроется на <http://localhost:5173>. Чтобы браузер открывался сам: `npm run dev -- --open`.

| Команда | Что делает |
| --- | --- |
| `npm run dev` | дев-сервер с горячей перезагрузкой |
| `npm run build` | проверка типов + сборка в `dist/` |
| `npm run build:single` | сборка в один файл `dist-single/index.html` |
| `npm run preview` | локальный просмотр собранной версии |
| `npm run typecheck` | только проверка типов |

## Что умеет

**Представления**

- **Обзор** — плитки (открыто, просрочено, выполнено за период, в работе),
  график выполненного по дням, приоритеты, задачи по проектам, ближайшие сроки.
  Период переключается на 7 / 14 / 30 дней, у каждого графика есть вид таблицей.
- **Сегодня** — задачи по корзинам: просрочено, сегодня, завтра, ближайшая неделя, позже, без срока.
- **Таблица** — правка прямо в строке, группировка по статусу / проекту / приоритету,
  сортировка, перетаскивание строк (в том числе между группами).
- **Доска** — канбан с перетаскиванием карточек между колонками.
- **Календарь** — месяц; карточки переносятся между днями, «+» в дне создаёт задачу с этим сроком.

**Задача** — статус, приоритет, проект, срок, теги, чек-лист подзадач, заметки.

**Горячие клавиши** — `⌘K` / `Ctrl+K` открывает поиск по задачам и создание новой,
`Esc` закрывает панель, меню и палитру, `Enter` в подзадаче добавляет следующую.

## На чём я остановился в других проектах

Трекер умеет подтягивать сводку из локальных сессий Claude Code — по одной
задаче на проект, с последним запросом в заметке.

```bash
npm run sync:claude
```

Скрипт читает `~/.claude/projects`, берёт из свежей сессии каждого проекта тему,
папку, ветку и последние реплики и складывает всё в `claude-tasks.json`.
Затем в сайдбаре — **«Подтянуть из Claude Code»** и выбрать этот файл.

Повторный запуск ничего не ломает: задачи опознаются по проекту, известные
обновляются, новые добавляются. Статус, срок и приоритет остаются вашими —
выгрузка переписывает только заметку, поэтому отмеченное «Готово» таким и остаётся.

`claude-tasks.json` лежит в `.gitignore` и остаётся на вашей машине: тексты
запросов бывают личными, а репозиторий публичный. В сайт он не попадает и
никуда не отправляется — вы выбираете файл вручную.

Если сессии Claude Code хранятся не в домашней папке, путь задаётся переменной:

```bash
CLAUDE_PROJECTS=/путь/к/projects npm run sync:claude
```

## Где живут данные

Всё хранится в `localStorage` браузера, отдельно по каждому устройству и профилю:

- `tracker.data.v1` — задачи и проекты;
- `tracker.ui.v1` — настройки вида (текущее представление, группировка, сортировка);
- `tracker.seeded` — отметка, что демо-данные уже создавались (чтобы не появлялись снова).

Синхронизации между устройствами нет. Для переноса и бэкапа — пункты сайдбара
**«Сохранить резервную копию»** (выгружает JSON) и **«Загрузить из копии»**
(заменяет текущие данные содержимым файла, спрашивает подтверждение).

Чтобы начать с чистого листа: удалите демо-задачи вручную либо очистите
хранилище сайта в настройках браузера.

## Структура

```
src/
  main.ts          точка входа: подключает стили и поднимает приложение
  app.ts           перерисовка, сохранение фокуса, создание задачи
  events.ts        все обработчики: клики, ввод, клавиши
  state.ts         состояние, сохранение, демо-данные
  storage.ts       адаптер хранилища (сейчас только localStorage)
  tasks.ts         операции над задачами, выборки, группировка, чипы
  dnd.ts           перетаскивание
  exporters.ts     Markdown и резервные копии
  types.ts         типы предметной области
  constants.ts     статусы, приоритеты, цвета, названия месяцев
  icons.ts         набор SVG-иконок
  util.ts          DOM-хелперы, даты, склонения
  ui/              меню, панель задачи, палитра команд, сайдбар и шапка, тултип
  views/           обзор, таблица, доска, календарь, сегодня
  styles/          токены, раскладка, компоненты, представления, дашборд, адаптив
```

Модули не импортируют `app.ts` напрямую — перерисовку зовут через `bus.ts`,
иначе получается цикл импортов.

## Оформление

Светлая и тёмная темы переключаются вслед за системной настройкой: все цвета
заданы токенами в `styles/tokens.css`, в тёмной переопределяются только значения.

Цвета графиков (`--viz-*`) подобраны отдельно от цветов чипов и проверены на
различимость при дальтонизме и контраст к поверхности карточки в обеих темах.
Если будете менять их — проверяйте пару «в работе / готово» заново.

## Публикация

`npm run build` кладёт статику в `dist/` — её можно раздавать откуда угодно.
В `vite.config.ts` стоит `base: "./"`, поэтому сборка работает и из подпапки,
например на GitHub Pages.

- **GitHub Pages** — запушить `dist/` в ветку `gh-pages` или собрать в Actions.
- **Netlify / Vercel** — команда сборки `npm run build`, каталог публикации `dist`.
- **Свой сервер** — см. ниже.

### Свой сервер с nginx

В папке `deploy/` лежит готовый сценарий: он раскладывает сборку в
`/var/www/tracker` и включает отдельный сайт, не трогая остальные.

```bash
npm run build
tar -czf tracker-dist.tar.gz -C dist .
scp tracker-dist.tar.gz deploy/deploy.sh deploy/nginx-tracker.conf root@СЕРВЕР:/tmp/
ssh root@СЕРВЕР "cd /tmp && bash deploy.sh /tmp/tracker-dist.tar.gz"
```

Скрипт создаёт только свой конфиг, перед перезагрузкой проверяет `nginx -t`
и откатывает изменения, если проверка не прошла — соседние сайты остаются целы.
Прошлая версия трекера сохраняется в `/var/www/tracker.old`, откат:

```bash
rm -rf /var/www/tracker && mv /var/www/tracker.old /var/www/tracker && systemctl reload nginx
```

Домен и каталог меняются переменными: `DOMAIN=… ROOT=… bash deploy.sh …`.
HTTPS — `certbot --nginx -d ваш.домен` после первой выкладки.

Обычную сборку нужно отдавать по http: скрипт подключается как модуль, а модули
браузер не грузит с `file://`. Если хочется просто двойного клика по файлу —
`npm run build:single` собирает `dist-single/index.html`, куда вшиты и стили,
и скрипт. Такой файл открывается с диска, его можно положить в облачную папку
или носить на флешке. Данные при этом привязаны к тому месту, откуда файл открыт:
перенесёте файл — перенесите и копию через «Сохранить резервную копию».

Приложение работает офлайн после первой загрузки, кроме шрифтов: они тянутся
с Google Fonts. Если нужна полная автономность — положите Inter и Source Serif 4
в проект и замените `<link>` в `index.html` на локальный `@font-face`.
